MP10 Reason Bridge 1.4 — optional MIDI diagnostics

Version 1.3 includes the CoreMIDI timestamp correction confirmed working by
the project owner with MP10, Reason 14 and macOS Tahoe. Diagnostics are
optional; use Mackie Control (MCU) mode for normal transport control.

CONFIRMED REASON CONFIGURATION

Manufacturer: Mackie
Model:        Control
Input:        MP10 Reason Bridge
Output:       MP10 Reason Bridge Feedback

Select these ports inside Reason. In the bridge app, select the physical
MP10/interface MIDI input, such as USB-MIDI. Start the bridge before Reason.
Keep the real MP10 configured as your master keyboard for playing notes.
Avoid duplicate active entries reading the bridge port. Clear old manual
transport overrides when testing the native Mackie configuration.

UPGRADING

Quit the older bridge and Reason, replace the app with v1.4, start the bridge,
then reopen Reason. Re-select the current ports in Reason if necessary.
Custom MIDI-note assignments are preserved.

AUTOMATIC RECONNECTION

Select the physical input once. Its CoreMIDI ID, display name and available
manufacturer/model properties are saved. The app reconnects after restart
or hardware replug. A changed driver ID falls back to one matching identity;
ambiguous devices require manual selection. A missing saved device produces
Waiting for ...; the app retries every two seconds and on CoreMIDI changes.
Choosing the empty Select input entry deliberately disables auto-reconnect.
Virtual Reason port IDs are retained from v1.4 onward. A first-time upgrade
may require one port re-selection in Reason. Quit other bridge instances
if a persisted virtual port identity cannot be restored.

RAW MIDI LOG

Enable Raw MIDI log, click Clear Log, test a few buttons, then click Copy Log.
The text contains the selected mode, source, OS version and latest 1000 lines.

INPUT -> BRIDGE: bytes received from the selected hardware input.
HOST -> BRIDGE: feedback received from Reason on the bridge Feedback port.
BRIDGE -> HOST: bytes submitted by the bridge to its virtual output; this
is not confirmation that Reason acted on them.

The leading time is monotonic seconds at callback processing time, not the
original hardware timestamp. Output lines include host_ticks, the actual
nonzero Mach timestamp submitted with that generated packet. Long input
callbacks are displayed in 128-byte chunks; boundaries are not necessarily
MIDI-message boundaries. SysEx may span several input callbacks.

For example, the MP10 sends MMC Play as F0 7F 7F 06 02 F7. The bridge turns it
into MCU press 90 5E 7F and release 90 5E 00 after 80 ms. Different input and
output bytes are expected: that conversion is the purpose of the bridge.

REFERENCE CAPTURE

1. Keep the reference device (such as UFX1604 in Mackie mode) connected
   directly to Reason with its known working configuration.
2. In the bridge, choose Monitor input only, then select the reference input.
3. Clear Log, press/release Play, Stop, Record, Rewind, Fast Forward once each.
4. Copy Log before changing the selected source, and label it with the device.
5. Switch back to Mackie Control (MCU) and the MP10 input for normal use.

Monitor-only mode sends no transport output. It records hardware-to-Mac
traffic; it cannot intercept Reason messages sent directly to physical
hardware. Reason-to-bridge feedback is visible only when Reason's Output
is MP10 Reason Bridge Feedback.

TIMESTAMP FIX

Earlier builds passed timestamp 0 to MIDIReceived. That value does not mean
"now" for a virtual MIDI source. Version 1.3 assigns current Mach host time
to generated press, release and handshake packets. This fixed the reported
native Mackie behavior. See issue #1 and Apple's CoreMIDI documentation:
https://github.com/rommelfs/mp10-reason-bridge/issues/1
https://developer.apple.com/documentation/coremidi/midireceived(_:_:)

TESTS

--self-test checks saved-input matching/persistence and the production packet builder (valid current timestamps,
reference payloads, SysEx, size limits and delivery errors) and protocol logic.
--integration-test requires a macOS graphical session and available CoreMIDI;
it verifies virtual-port delivery, both output modes, preferences, feedback,
handshake, received nonzero timestamps, input replug with resumed translation,
explicit disconnect and virtual-port identity restoration. That automated integration test
is unavailable in the restricted development environment; the physical
Reason setup was confirmed by the project owner.

No diagnostic data is uploaded automatically. Copy Log copies text only.
